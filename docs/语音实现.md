# 语音实现文档（TTS）

> 目标环境：**Windows 电脑 / 浏览器**。
> 状态：**已实现并端到端验收通过**（2026-09-29）。
> 选型依据见 [`语音方案.md`](语音方案.md)，本文只写「怎么落地的」与「踩过哪些坑」。

---

## 一、一句话结论

**用 Node 22 内置的 `WebSocket` 直连 edge-tts 的 WebSocket 端点**，
在 `/api/tts` 里把文本合成 MP3 字节直接返回给前端。**不需要 Python、不需要子进程、不需要 API Key。**

这条路能走通的前提是三条硬约束同时成立：

| 约束 | 原因 |
|---|---|
| **不能用子进程调 Python `edge-tts`** | 本机 Node 派生任何子进程都报 `EBUSY`（Git Bash 句柄争用）；Vercel 也没有 Python 运行时 |
| **必须是 Node.js runtime** | `edge runtime` 不支持 WebSocket |
| **必须用标准 WebSocket 实现** | 自己搓 TLS + RFC6455 握手，服务端**一个帧都不回**（详见第五节） |

## 三、数据流

```
孩子发一句
   → /api/chat 流式返回 AI 回复
   → 回复落地，speech.speak(text, bubbleId)
   → POST /api/tts { text, voice, rate, pitch, scenarioSlug }
   → lib/tts-cache: 内存? → 磁盘? → 都没有才真合成
   → lib/tts.js: WebSocket 连 edge-tts，收 MP3 字节
   → 返回 audio/mpeg（强缓存 immutable）
   → 前端 new Audio(blobUrl).play()
   → 若失败：console.warn 后静默收场，界面文字照常
```

**关键设计：语音是「锦上添花」，任何环节坏掉都不影响闯关主流程。**
前端所有失败分支都只清状态、不弹错误。

## 四、edge-tts 逆协议要点（全部为本机实测结论）

端点：

```
wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1
  ?TrustedClientToken=6A5AA1D4EAFF4E9FB37E23D68491D6F4
  &Sec-MS-GEC=<令牌>
  &Sec-MS-GEC-Version=1-143.0.3650.75
```

### 4.1 `Sec-MS-GEC` 令牌

```js
ticks = floor(nowSec) + 11644473600      // 转到 Windows FILETIME 纪元
ticks -= ticks % 300                     // 5 分钟窗口对齐
ticks = floor(ticks * 1e7)               // 转 100ns 单位
token = SHA256(ticks + TRUSTED_TOKEN).hex().toUpperCase()
```

**必须保持这个浮点运算顺序。** 改成 BigInt 会得到不同字符串 → 令牌不匹配 → 403。

### 4.2 `X-Timestamp` 是 JavaScript 风格日期，不是 ISO 8601

```
Tue Sep 29 2026 08:13:45 GMT+0000 (Coordinated Universal Time)
```

⚠️ **SSML 消息的 `X-Timestamp` 末尾要额外补一个 `Z`。**
这正是 Python edge-tts 上游注释里写的「This is not a mistake, Microsoft Edge bug.」

用 `toISOString()` 会导致：**握手 101 成功，但服务端一个帧都不回就静默关闭** ——
这是本项目最难排查的一个坑（见第六节）。

### 4.3 `voice` 必须是 .NET 风格全称

```
Microsoft Server Speech Text to Speech Voice (en-US, AndrewNeural)
```

不能写 `en-US-AndrewNeural`。`lib/tts.js` 的 `toFullVoiceName()` 负责转换。

### 4.4 其他固定值

| 项 | 值 | 备注 |
|---|---|---|
| `Origin` | `chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold` | Edge 朗读扩展固定 ID。**随机 UUID 直接 403** |
| Chromium 版本 | `143.0.3650.75` | **必须跟随上游**。实测 130.x 已失效返回 403 |

### 4.5 SSML 规范（差一个字符就 `code=1007 SSML is invalid`）

```xml
<speak version='1.0' xmlns='http://www.w3.org/2001/10/synthesis' xml:lang='en-US'>
  <voice name='Microsoft Server Speech Text to Speech Voice (en-US, AndrewNeural)'>
    <prosody pitch='-12%' rate='-12%' volume='+0%'>
      Hello!
    </prosody>
  </voice>
</speak>
```

- 属性用**单引号**
- **不要**加 `mstts` 命名空间声明
- `<prosody>` 的 `volume` **必须存在**（`volume` 缺失会报 SSML 非法，而非忽略）
- **不要**加 `<mstts:webvtt/>` 空标签

### 4.6 ★ 二进制帧结构（最容易搞错的地方）

```
[2 字节大端 headerLen][header 文本（headerLen 字节）][MP3 数据]
```

实测 `headerLen` 恒为 **128**，header 形如：

```
X-RequestId:...\r\nContent-Type:audio/mpeg\r\nX-StreamId:...\r\nPath:audio\r\n
```

```js
const headerLen = buf.readUInt16BE(0);
const audioStart = 2 + headerLen;
chunks.push(buf.subarray(audioStart));
```

**如果写成 `buf.subarray(2)`**，header 文本会被混进 MP3 ——
输出文件开头是 `58 2d 52 65`（`X-Re`）而不是 `ff f3`。
这个错误不会报错，只会得到一个损坏的音频文件。

### 4.7 文本帧按 `Path:` 区分

`turn.start` / `response` / `audio.metadata` / `turn.end`。
**收到 `turn.end` 才收尾**，不要用超时猜。

## 五、★ 最大技术结论：不要自己搓 WebSocket

调试过程中实现过一版「手工 TLS + RFC6455 握手 + 自研帧解析」。结果：

| 实现 | HTTP 层 | 收到帧数 |
|---|---|---|
| Python aiohttp（参考实现） | 逐头一致 | 25 帧 ✅ |
| 自研 Node（TLS + 手工握手） | 逐头对照**完全一致** | **0 帧** ❌ |
| **Node 22 内置 `WebSocket`（undici）** | — | **一次即通** ✅ |

逐头核对过 `Host` / `Upgrade` / `Connection` / `Sec-WebSocket-Key` / `Sec-WebSocket-Version` /
`Origin` / `User-Agent` / `Accept` / Cookie，甚至照抄头顺序，Python 能收帧而 Node 收 0 帧。

**推断差异在 TLS 层细节（ALPN / 扩展顺序 / 记录分片），肉眼无法对齐。**

→ 结论已写入 `lib/tts.js` 文件头：**不要重造 WebSocket，用标准实现。**

## 六、缓存设计

**为什么缓存是功能的一部分而不是优化：** 孩子会反复点「重听」。
命中缓存 < 10ms，未命中 3.5-5 秒。

### 内容寻址

```
key  = sha256(voice | rate | pitch | volume | style | text)
路径 = .tts-cache/<key 前 2 位>/<完整 key>.mp3
```

同一文本 + 同一音色永远映射到同一文件，因此响应可带
`Cache-Control: public, max-age=31536000, immutable`。

### 三级查找

1. **内存**（LRU，上限 60 条）—— 同一会话内点重听走这里，0ms
2. **磁盘**（`.tts-cache/<xx>/<hash>.mp3`）—— dev server 重启后仍然命中
3. **合成** —— 只有前两级都落空才真的连 edge-tts

### 并发去重

`inflight` Map 记录「正在合成的 key」。同一文本并发请求时共享同一个 Promise，
避免重复合成。前端的快捷芯片连点会真实触发这个场景。

### Vercel 降级

Vercel Serverless 文件系统**只读**。`writeToDisk` 静默返回 false，
退化为纯内存缓存（同一实例内仍有效）。**不需要配置任何东西，自动降级。**

## 七、接口约定

### `POST /api/tts`

```json
{ "text": "Passport, please.", "voice": "en-US-AndrewNeural",
  "rate": "-12%", "pitch": "+0Hz", "scenarioSlug": "airport-checkin" }
```

| 响应头 | 含义 |
|---|---|
| `Content-Type` | `audio/mpeg` |
| `Cache-Control` | `public, max-age=31536000, immutable` |
| `X-TTS-Cache` | `memory` / `disk` / `miss` |
| `X-TTS-Voice` | 实际使用的音色（可能来自场景绑定而请求未传） |
| `X-TTS-Ms` | 服务端耗时 |

**音色优先级**：请求体 `voice` → 场景绑定的 `characterVoice` → `en-US-AriaNeural`。

**上限**：800 字符。孩子的单句回复远不到这个长度。

**鉴权**：与 `/api/chat` 同一道门（`requireAccess`），未登录返回 401。

### `GET /api/tts`

自检，返回 Node 版本与「是否有内置 WebSocket」：

```json
{ "ok": true, "engine": "edge-tts (via Node built-in WebSocket)", "node": "v22.22.2" }
```

**如果 `ok:false`，说明 Node < 21，需要升级运行时。**

## 八、场景音色绑定

`docs/voice.sql` 给 5 个场景各绑一个音色。原则：**性别与角色一致，同性别角色之间要有区分度**
（否则五个场景听起来像同一个 AI，角色人格就废了）。

| 场景 | 角色 | 音色 | 语速 |
|---|---|---|---|
| `airport-checkin` | Max | `en-US-AndrewNeural` | -12% |
| `shop-compare` | Nico | `en-US-BrianNeural` | -8% |
| `restaurant-order` | Momo | `en-US-JennyNeural` | -12% |
| `impromptu-speech` | Ivy | `en-US-AvaNeural` | -8% |
| `club-interview` | Sam | `en-US-AnaNeural` | -5%（童声） |

统一放慢 5–12%：**孩子听英语，正常语速跟不上。**

执行：

```bash
node scripts/run-sql.mjs docs/voice.sql
```

列已存在时会归类为 SKIP，**可重复执行**。

## 九、前端行为细则

| 行为 | 实现 | 为什么 |
|---|---|---|
| **进场景自动朗读开场白** | `enter()` 里 `speak(d.openingLine, 'opening')` | 孩子不用读英文，第一屏就有声音 |
| **AI 回复自动朗读** | 流式收尾后 `speak(finalText, \`ai-${n}\`)` | 这是语音功能的主要价值 |
| **气泡重听按钮** | `speak(text, bubbleId, { force: true })` | `force` 忽略静音开关 —— 用户主动要求就该播 |
| **同一时刻只播一条** | 播放前 `pause()` 上一条 + `abort()` 旧请求 | 连点重听时多条叠在一起完全听不清 |
| **静音开关持久化** | `localStorage['ienglish.tts.muted']` | 关掉后下次打开不该突然响起来（吓到孩子、惊到家长） |
| **朗读中高亮** | `.bubble.speaking` 绿色描边 | 给孩子「就是这条在响」的视觉锚点 |
| **失败静默降级** | `console.warn` 后只清状态 | 语音坏掉绝不能影响闯关 |
| **blob URL 缓存** | 进程内 Map，上限 40 条，超出 revoke 最旧 | 重听走本地 blob，不再发请求 |
| **结算页播报** | `useEffect` 由 `finished` 驱动 | 只念一次；依赖里**刻意不放 `speech`**（useSpeech 每次渲染返回新对象，放进去会疯狂重复朗读） |

### 一个易踩的依赖陷阱

```js
// ❌ 错：speech 每次渲染都是新对象 → 结算页无限重复朗读
useEffect(() => { speech.speak(...) }, [finished, speech]);

// ✅ 对：只由 finished 驱动
useEffect(() => { speech.speak(...) }, [finished]);
```

## 十、验收

```bash
# 1) 服务端自检
curl --noproxy '*' http://127.0.0.1:3000/api/tts
# → {"ok":true,...}

# 2) 前端端到端（需要 token，否则全部 401）
TOK=$(node scripts/mint-token.mjs)
BASE=http://127.0.0.1:3000 IE_AUTH="$TOK" \
  NODE_PATH="C:/Users/lenovo/.workbuddy-ai/binaries/node/workspace/node_modules" \
  node scripts/verify-tts-ui.cjs
```

`verify-tts-ui.cjs` 的 13 项断言：

```
PASS  开场白气泡渲染
PASS  进场景自动朗读（发出 /api/tts 请求）
PASS  自动朗读文本与开场白一致
PASS  朗读中高亮（.bubble.speaking）
PASS  AI 气泡带重听按钮
PASS  点击重听无异常
PASS  顶栏存在声音开关
PASS  静音状态写入 localStorage
PASS  静音后按钮显示 off 状态
PASS  静音下点重听仍可用（force 生效）
PASS  静音下 AI 回复不自动朗读
PASS  恢复声音并写回 localStorage
PASS  无未捕获 JS 异常
```

### ★ 验收必须带 token，否则会得到极具误导性的结果

`/admin` 启用访问口令后，`/api/tts` 返回 401。此时不带 Cookie 跑脚本会看到：

- 页面正常渲染、开场白气泡正常显示
- **但一次合成都没有发生**

看起来像「自动朗读功能没生效」，实际是鉴权把请求全挡掉了。
`mint-token.mjs` 用同一个 `SETTINGS_SECRET` 本地签发合法 Cookie。

## 十一、云端部署（Vercel）注意事项

> ★ 部署到 Vercel 后「没声音」，绝大多数不是代码缺陷，而是下面这几条。
> 按 11.1 → 11.2 → 11.4 → 11.3 的顺序排查。

### 11.1 代码必须先推送（最常见原因）

TTS 全部代码若仍停留在本地（未 commit / 未 push），Vercel 上跑的是**旧版本**，
该版本没有 `/api/tts` 路由。前端请求它得到 **404**，触发静默降级 ——
表现就是「完全没有声音」。

**判断方法**：`git status` 看到 `?? lib/tts.js`、`?? app/api/tts/` 这类未跟踪条目，
或 GitHub 上最新 commit 不是 TTS 那次提交，即属此情况。

**为什么容易被误判为「功能坏了」**：这种情况**不会报错**，只是没声音 ——
因为前端刻意对语音失败做了静默降级。这是设计取舍（语音坏了不能影响闯关），
副作用是「部署漏了」也被静默吞掉。

### 11.2 Node 运行时必须 ≥ 21

`lib/tts.js` 依赖 Node 内置的 `WebSocket`（Node 21 引入，22 稳定）。
Node 20 及以下**没有这个全局对象**，`new WebSocket()` 抛 `ReferenceError`。

`package.json` 已声明：

```json
"engines": { "node": "22.x" }
```

Vercel 据此选择运行时。**若在 Vercel 项目设置里手动指定过 Node 版本，以设置为准，需确保是 22.x。**

**自检**：访问 `https://<域名>/api/tts`，看 `ok` 与 `node`：

```json
{ "ok": true, "engine": "edge-tts (via Node built-in WebSocket)", "node": "v22.x.x" }
```

`ok: false` 即表示当前运行时没有内置 WebSocket。

### 11.3 出站 WebSocket 是唯一的未知项

Vercel 的 Node.js 函数底层是 AWS Lambda 形态。**入站** WebSocket 有官方支持
（但有硬时长上限），而**出站** WebSocket（本方案要用的方向）**官方没有明确承诺**。

- Lambda 允许出站 TCP，Node 的 `net`/`tls` 可用，因此**理论上可行**
- 但 undici 的内置 WebSocket 在 serverless 冷启动环境存在已知的边缘兼容问题
- **本项目未在 Vercel 实测过**（本地 Node 22 实测通过）

→ 部署后**必须实测**：`POST https://<域名>/api/tts` 看是否返回 `audio/mpeg`。

若确认不通，两条路：

1. 改用 `ws` npm 包（纯 Node 实现，不走 undici）
2. 依赖前端已有的**浏览器内置语音兜底**（见 11.5）—— 音色会变，但至少有声音

### 11.4 鉴权：云端 `/admin` 启用口令后必须登录

`/api/tts` 与 `/api/chat` 共用鉴权。云端启用访问口令后，**未登录时返回 401**，
前端静默降级 → 没声音。

**这是「部署成功但仍没声音」的第二大原因**（仅次于 11.1）。
打开云端 `/admin` 登录一次即可。

### 11.5 两级降级链路

语音失败时有两条防线，都是静默的：

| 层级 | 触发条件 | 结果 |
|---|---|---|
| 第一道：edge-tts | 正常路径 | 角色音色，音质好 |
| 第二道：浏览器 `SpeechSynthesis` | 服务端合成失败 | **有声音**，但音色取自用户设备，与角色音色不一致 |
| 都不可用 | 浏览器也不支持 | 完全静音，仅 `console.warn` |

第二道是刻意设计的 —— **「有声音但音色不对」远好于「完全没声音」**。
代价是五个场景的角色区分度会丢失（都变成系统音色）。

### 11.6 缓存在 Vercel 上自动退化

Serverless 文件系统只读，`writeToDisk` 静默返回 false，退化为**纯内存缓存**
（同一实例内仍命中）。功能不受影响，**无需配置**。
观察响应头 `X-TTS-Cache` 可判断命中情况（`memory` / `disk` / `miss`）。

### 11.7 云端自检三步

```bash
# 1) 运行时是否具备内置 WebSocket
curl https://<域名>/api/tts

# 2) 能否真的合成（需带登录 Cookie）
curl -X POST https://<域名>/api/tts \
  -H "Content-Type: application/json" \
  -H "Cookie: ie_auth=<登录后的 Cookie>" \
  -d '{"text":"Passport, please.","scenarioSlug":"airport-checkin"}' \
  -D - -o /tmp/t.mp3 | grep -i "x-tts\|content-type"
xxd -l 4 /tmp/t.mp3   # 应为 fff3xxxx

# 3) 看 Vercel 函数日志（Runtime Logs）
#    若第 2 步返回 502，日志里会有 [api/tts] 合成失败: <原因>
```

## 十二、排查手册

| 现象 | 根因 | 修复 |
|---|---|---|
| **★ 云端完全没声音、且无任何报错** | 代码未推送（`/api/tts` 404）或云端未登录（401） | 见第十一节 11.1 / 11.4 —— **最高频原因** |
| **403 Forbidden**（握手被拒） | Chromium 版本号过期 / Origin 用了随机 UUID | 版本号跟上游；Origin 用固定扩展 ID |
| **`code=1007 SSML is invalid`** | 属性用了双引号 / 有 `<mstts:webvtt/>` / 缺 `volume` | 单引号、删空标签、补 `volume='+0%'` |
| **握手 101 成功但 0 帧、连接静默关闭** | `X-Timestamp` 用了 ISO 8601 | 改 JS 风格日期；SSML 消息末尾补 `Z` |
| **输出文件开头是 `58 2d 52 65`** | 二进制帧按 `subarray(2)` 取，header 混进去了 | 按 `readUInt16BE(0)` 定位音频起点 |
| **自研 WebSocket 收 0 帧** | TLS 层细节无法对齐 | **改用 Node 内置 `WebSocket`** |
| **`GET /api/tts` 返回 `ok:false`** | Node < 21 无内置 WebSocket | 升级 Node 运行时 |
| **本地能合成、Vercel 报错** | WebSocket 被墙或 runtime 不是 nodejs | 检查 `export const runtime = 'nodejs'` |
| **有文字没声音，控制台无报错** | 浏览器自动播放策略拦了 `audio.play()` | 属预期。需要用户手势；`--autoplay-policy=no-user-gesture-required` 可绕过（仅测试用） |

### 调试建议

- 所有 Node/Python 命令前加 `unset http_proxy https_proxy ALL_PROXY HTTP_PROXY HTTPS_PROXY`
  —— **代理会干扰 WebSocket 握手**
- 测本地服务还要加 `--noproxy '*'`
- 需要看原始帧结构时，把二进制帧 dump 成文件再看前 16 字节，
  **不要靠 `console.log` 猜**

## 十三、成本与风险

| 项 | 说明 |
|---|---|
| **费用** | **零**。edge-tts 无需 API Key |
| **风险** | 它是**调用 Edge 浏览器内部的未公开接口**，非官方承诺 SLA。微软可能随时调整端点或令牌算法 |
| **失效表现** | 403 / 返回非 MP3 |
| **兜底** | ① `looksLikeMp3()` 校验拦下坏数据，不污染缓存<br>② 前端静默降级，界面文字不受影响<br>③ 真失效时改回浏览器内置 `SpeechSynthesis`（音质差但零依赖） |

**建议**：`X-TTS-*` 响应头已暴露缓存状态与音色，方便线上观察命中率。
若发现大量 `miss` + 高耗时，说明缓存键设计需要调整（比如文本里带了随机后缀）。
