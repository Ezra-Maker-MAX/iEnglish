# 语音功能方案选型（免费路线）

> 结论先行：**有免费方法，但要分「TTS（AI 说话）」和「ASR（听孩子说话）」两条线分别决策**，
> 且**真正决定孩子体验的不是成本，而是童声识别率**。
>
> 本文所有平台能力均为 2026-09-29 本机实测，非文档抄录。

---

## 一、先排除一条路：当前 LLM 平台没有语音能力

**实测结论：agnes 平台只有文本 / 图像 / 视频三类模型，没有任何语音模型。**

证据（2026-09-29 实测）：

```
GET  /v1/models          → 12 个模型，全部是 agnes-2.x / 3.0 / image / video，无 TTS/ASR
POST /v1/audio/speech    → 400 "Model name not specified"
                            指定 tts-1 / gpt-4o-mini-tts / cosyvoice-v1 … → 503 no available channel
POST /v1/audio/transcriptions → 503 "No available channel for model whisper-1"
POST /v1/audio/voices    → 404 Invalid URL
```

**关键推断**：路由存在（说明是标准 OneAPI 类网关）、但**没有任何语音渠道被开通**。
`no available channel` 与之前 `agnes-1.5-flash` 的表现一致 —— 这类网关的
「路由支持」不等于「渠道已开通」，**必须真实调用验证**。

→ 所以语音必须**外接第三方**，不能在现有 Key 里解决。

---

## 二、TTS（让 AI 说话）：免费方案成熟，推荐直接上

### 推荐：edge-tts（微软 Edge 的在线合成服务）

| 项 | 值 |
|---|---|
| 成本 | **免费，无需 API Key** |
| 音质 | 接近 Azure 商业级，明显优于系统内置 |
| 语言 | 多语言，中英文音色都很自然 |
| 调用方式 | ① Python 库 `edge-tts`（本地/服务端生成 mp3）<br>② 封装成 OpenAI 兼容 HTTP 接口供前端调用 |
| 风险 | 属于**调用 Edge 浏览器内部的未公开接口**，非官方承诺的 SLA；微软随时可能调整 |

**为什么推荐它**：孩子端最需要的是「AI 说英语要好听」。edge-tts 的英文音色
（如 `en-US-AriaNeural` / `en-GB-SoniaNeural`）自然度足够，而成本为零。

**降级方案：浏览器内置 `SpeechSynthesis`**（成本同样为零、零基础设施）

```js
const u = new SpeechSynthesisUtterance(text);
u.lang = 'en-US';
u.rate = 0.9;                    // 孩子听，放慢
speechSynthesis.speak(u);
```

优点：完全免费、无需联网中转、实现量极小。
缺点：**音质取决于用户设备**（Windows 的英文音色尚可，安卓/iOS 差异大），
且音色一致性不可控 —— 同一个角色在不同设备上声音不同。

**建议**：先用 `SpeechSynthesis` 跑通交互（半天工作量），
体验不满意再换 edge-tts（音色统一、可控）。

## 三、ASR（听孩子说话）：★★ 这才是真正的难点

### 3.1 为什么难：童声识别率是硬伤

**儿童语音识别准确率显著低于成人**，两个根因：

1. **音高差异** —— 儿童基频明显高于成人，主流 ASR 的声学模型以成人语料训练，对高频段建模不足。
2. **发音不标准** —— 孩子（尤其英语初学者）发音偏离标准音素，与训练数据分布不匹配。

**对本项目的具体影响**：孩子说英语发音本就不标准，ASR 再把「不标准的英语」
识别错，会形成**双重误差**。AI 收到错误文本后给出牛头不对马嘴的回复，
孩子的体验是「TA 听不懂我说话」—— 比没有语音功能更糟。

> ⚠️ **这条风险必须在动手前拿自己孩子实测验证。**
> 建议先做一个极简 demo：录 10 句孩子的英语，分别过几个候选 ASR，人工比对识别结果。
> 这一步的投入（约 1 小时）能避免后面几天的白工。

### 3.2 候选方案对比

| 方案 | 成本 | 童声表现 | 国内可用 | 实现复杂度 |
|---|---|---|---|---|
| **浏览器 `webkitSpeechRecognition`** | 免费 | 尚可（Google 模型） | ❌ **国内不可用** | 极低 |
| **讯飞语音听写** | 每日 500 次免费 | ★ 对中文童声有优化 | ✅ | 中（WebSocket） |
| **Groq Whisper** | 免费额度（约 1000 次/天级） | 一般（成人语料为主） | ⚠️ 需确认可达性 | 低（OpenAI 兼容） |
| **sherpa-onnx / FunASR（本地）** | 免费 | 可用专用童声模型优化 | ✅ 离线 | 高（要自己部署） |

### 3.2b 通达性实测（本机，2026-09-29）

```
api.groq.com/openai/v1/models   → HTTP 401   ✅ 可达（401 = 需鉴权，非被墙）
www.xfyun.cn                    → HTTP 200   ✅ 可达
speech.platform.bing.com        → HTTP 400   ✅ 可达（400 = 缺参数，非被墙）
```

三者本机都能通。**注意**：这是本机（带代理环境变量 unset 后）的结果，
家庭实际网络环境可能不同 —— 尤其 Groq 在国内不同运营商下差异较大，
**上线前务必在目标使用环境的网络上复测**。

### 3.3 ★ 关键坑：浏览器内置识别在国内用不了

`webkitSpeechRecognition` 看起来是最优解（免费 + 一行代码），但**它依赖 Google 的
Web Speech 服务**：

- 国内网络环境下请求会超时或拒绝（表现为 `network` 错误 / `request error`）
- 长期高频使用还可能触发 Google 免费配额限制导致 IP 被封
- **仅 Chromium 系（Chrome/Edge）支持**，Firefox / Safari 行为不一致

→ **对本项目的目标用户（国内家庭）来说，这条路实际上不可用。**
不能因为「代码简单」就选它，否则做出来孩子打开就是坏的。

### 3.4 现实推荐

**第一优先：讯飞语音听写**
- 中文互联网环境下稳定可达，这对国内家庭是**决定性优势**
- 创建应用后默认**每日 500 次**免费额度，另有一次性免费包（约 5 万次 / 90 天）
- 对中文童声有专门优化（国内童声数据积累最多）
- 代价：WebSocket 协议，不是 OpenAI 兼容，需要单独写适配层

**注意**：本项目是**英语**练习场景，但孩子是中文母语者说英语。
讯飞对「带口音的英语」的表现需要实测确认 —— 这是选型时最该验证的一点。

## 四、架构建议：不要一次做完

| 阶段 | 内容 | 工作量 | 价值 |
|---|---|---|---|
| **第 1 步** | 只做 **TTS**（AI 朗读回复） | 小 | 高 —— 孩子不用读英文长句，听力输入直接拉满 |
| **第 2 步** | 加 **ASR**（孩子语音输入） | 中 | 高，但**依赖童声识别率达标** |
| **第 3 步** | 语音打断 / 实时流式对话 | 大 | 中 —— 需要 WebSocket 常驻，注意 Vercel 连接上限 |

**强烈建议先做第 1 步。** 理由：

1. **TTS 的收益确定、风险几乎为零** —— 免费方案成熟，不依赖任何不确定的识别率。
2. 孩子「听」的需求比「说」更早出现 —— 当前纯文字界面里，孩子要**读** AI 的英文，
   对初学者是额外负担。让 AI 念出来，教学效果立刻提升。
3. **ASR 的效果高度不确定**，在实测孩子语音识别率之前，不应该投入架构改造。

---

## 五、⚠️ 架构约束提醒（本项目已踩过）

**如果第 3 步要做实时语音对话（常驻 WebSocket），必须注意 Vercel 的硬限制：**

- Vercel 原生支持 WebSocket，跑在 Fluid compute 上
- 但**连接有硬时长上限：Hobby 300s / Pro 800s**，官方明确「周期性断连是预期行为」
- **无机制可突破**

→ 所以**不能把 Vercel 当常驻语音网关**。可行做法：
- 短会话（单轮问答即建即断）—— 推荐
- 或把语音中转放到独立的常驻服务（如自建 WebSocket 服务）

另外，Route Handler 要跑 WebSocket **必须 `export const runtime = 'nodejs'`**，edge 不支持。

## 六、决策清单

请先回答这两个问题，我再动手：

1. **孩子用的设备是什么？**（Windows 电脑 / iPad / 安卓平板）
   → 决定 TTS 用 `SpeechSynthesis` 还是 edge-tts（音色一致性）
2. **是否接受接入讯飞？**（需注册开放平台账号）
   → 这是国内唯一稳妥的免费 ASR 路线

**我的建议顺序**：先做 TTS（1 天内可完成并验收）→ 拿孩子实测 ASR 识别率 →
再决定是否上语音输入。
