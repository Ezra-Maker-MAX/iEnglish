# 配置中心使用说明

## 为什么要把配置放数据库

传统做法是把 API Key、模型名写在环境变量里，改一次要去 Vercel 后台改一次、再触发一次重新部署。本项目把**除 Turso 连接凭据之外的所有配置**都存进了 Turso 数据库，通过网页 `/admin` 编辑，**保存即生效，无需重新部署**。

### 配置分层

| 配置项 | 存放位置 | 能否网页改 | 原因 |
|---|---|---|---|
| `TURSO_DATABASE_URL` | 环境变量 | ❌ | 自举依赖：没有它就读不到任何配置 |
| `TURSO_AUTH_TOKEN` | 环境变量 | ❌ | 同上 |
| `SETTINGS_SECRET` | 环境变量 | ❌ | 用于解密，若存库则失去意义 |
| API 地址 / 模型名 / API Key | **Turso `app_settings`** | ✅ | 高频变更 |
| 温度 / max_tokens | **Turso `app_settings`** | ✅ | 调优时需要反复试 |
| 访问口令哈希 | **Turso `app_settings`** | ✅ | 家长自己改 |

## 快速开始

### 1. 初始化配置表

```bash
# 用 turb 命令行
turso db shell ienglish < docs/settings.sql

# 或用 HTTP API（无需安装 CLI）
node -e "..." # 见 docs/settings.sql 头部注释
```

### 2. 配置环境变量

复制 `.env.example` 为 `.env.local`，填入 Turso 凭据，并生成一个 `SETTINGS_SECRET`：

```bash
openssl rand -hex 32
```

### 3. 打开配置页

```
http://localhost:3000/admin
```

首次进入时未设口令，任何人都能访问。**先设好了访问口令再上线**。

## 页面功能

### 模型配置

- **服务商预设**：一键填充 DeepSeek / 通义千问 / 硅基流动 / OpenAI / 月之暗面的地址与模型名
- **测试连接**：不发知识库、只发一个 `ping`，用最小开销验证 `base_url` / `key` / `model` 三者是否可用，并显示耗时与返回内容
- **API Key 掩码**：已保存的 Key 只显示 `sk-1a2b****ef90`，**明文永不回传前端**。输入新值即覆盖，留空即保持原值

### 访问保护

- 启用后，`/api/chat`、`/api/settings`、`/dashboard` 都要求先输入口令
- 口令以 `scrypt` 加盐哈希存储（不是明文、不是 MD5）
- 登录态用 HMAC 签名的 Cookie 承载，14 天有效，无服务端 session（适配 serverless）

### 环境变量说明表

页面底部列出仍需环境变量保存的项及其当前状态，避免忘记配。

## 安全设计

### 1. 密钥加密存储

配置 `SETTINGS_SECRET` 后，API Key 以 **AES-256-GCM** 加密后再入库：

```
enc:v1:<iv>:<authTag>:<ciphertext>
```

密钥由 `scrypt(SETTINGS_SECRET, 'ienglish-settings-v1')` 派生。这样即使 Turso 数据库被拖走，攻击者也拿不到明文 Key。

未配置 `SETTINGS_SECRET` 时退化为 `raw:` 前缀明文存储，页面顶部会持续告警。

官方文档：`https://www.npmjs.com/package/@libsql/client`

> GCM 模式自带完整性校验，密文被篡改会解密失败并抛错，已通过单测验证。

### 2. 明文不回传

`/api/settings` 的 GET 对 `is_secret=1` 的字段只返回掩码。前端「保持原值」时提交哨兵值 `__KEEP__`，后端识别后跳过该字段的更新。

### 3. 接口鉴权

`/api/chat` 背后是付费 API Key。启用访问口令后，未登录请求返回 401：

```json
{ "error": "未登录。请先访问 /admin 输入访问口令。" }
```

### 4. 白名单

`/api/settings` 的 POST 只接受白名单内的键，防止向 `app_settings` 塞入任意数据。

### 5. 数值校验

温度限 0~2、`max_tokens` 限 1~8192 整数、`base_url` 必须 `http(s)://` 开头。不通过的值一律拒绝，避免运行期报错。

## 代码结构

| 文件 | 职责 |
|---|---|
| `lib/settings.js` | 配置读写、AES-GCM 加解密、掩码、口令哈希、30 秒进程内缓存 |
| `lib/auth.js` | HMAC 签名 Cookie 的签发与校验、口令验证（定长比较防时序攻击） |
| `lib/llm.js` | 每次调用动态解析配置（库优先，环境变量兜底）；含 `testConnection()` |
| `app/api/settings/route.js` | GET 读配置（脱敏）/ POST 存配置 / PUT 测连通 |
| `app/api/auth/route.js` | 登录、登出、查询登录态 |
| `app/api/access/route.js` | 访问口令的设置与清除（含首次初始化引导） |
| `app/admin/AdminClient.js` | 配置页 UI |
| `proxy.js` | 边缘粗筛：无 Cookie 时把 `/dashboard` 重定向到 `/admin` |

## 已知约束

### 缓存的 30 秒窗口

配置有 30 秒进程内缓存，减少 serverless 冷启动时的数据库查询。写操作会主动清缓存，所以**网页上改完立即生效**；但如果绕过网页直接改数据库（如用 `turso db shell`），需等最多 30 秒。

### `proxy.js` 而非 `middleware.js`

Next.js 16 起，`middleware.js` 更名为 `proxy.js`。两个文件同时存在会导致：

```
Both middleware file "./middleware.js" and proxy file "./proxy.js" are detected.
```

并使所有路由返回 404。本项目已只保留 `proxy.js`。

### Edge runtime 限制

`proxy.js` 跑在 Edge runtime，**无法访问 Turso**（`@libsql/client` 是 Node 依赖）。因此它只做「有没 Cookie」的粗筛，真正的鉴权在页面与 API 层用 Node runtime 完成。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 配置页显示「无法解密」 | `SETTINGS_SECRET` 变了 | 重新填写 API Key |
| 保存后不生效 | 直连数据库改了值 | 等 30 秒，或在网页改 |
| 所有路由 404 | `middleware.js` 与 `proxy.js` 并存 | 删除 `middleware.js` |
| 测试连接 401 | Key 无效或额度耗尽 | 检查 Key 与账户余额 |
| 测试连接 `fetch failed` | `base_url` 错误或网络不通 | 核对地址，注意 `/v1` 后缀 |

> 注意：不同服务商对 `/v1` 后缀的要求不同。DeepSeek 用 `https://api.deepseek.com`（也可加 `/v1`），通义千问兼容模式必须带 `/v1`。填错会报 404 或 `fetch failed`。
